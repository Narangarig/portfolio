I build small, useful software — mostly on my own, moving quickly from an idea to something people can click on.

## How I work

Most projects start as a rough sketch: a problem worth solving, a shape for the solution, and a plan for what "done for now" looks like. I'd rather ship a narrow version this week than a complete one next quarter.

I care about:

- **Clarity over cleverness.** Code and interfaces should be easy to come back to after six months away.
- **Low-maintenance systems.** Static where possible, boring infrastructure, few moving parts to babysit.
- **Real content.** No placeholder text left behind — if a page exists, it says something true.

## Tools I reach for

`Markdown` for anything I write. Static hosting when a project doesn't need a server. A small number of dependencies, chosen deliberately rather than defaulted into.
